# 重构过程档案：roman_to_int（脱敏版）

> 本文件是 roman 演示的**过程证据**，不属于发布物四类，也不含引擎内部信息：
> 只记录方法论、可观察的判别结果与挂账；引擎内部机制、遥测与本机路径一律不在本仓存档。

## 骨架演进（v1 → v4）

- v1 ret 槽错 → v2 字符串手术不彻底 → v3 全局部槽 → v4 回执落写类步。
- v4 的结论沉淀为 [`docs/format.md`](../../docs/format.md) §十：`prim_ret` 指向的槽必须由**写类步**写入。
- 原设计为 CHAR_VAL 子组件（码点→值）+ 主组件 `call` 组合；因本仓执行器不含组合算子，
  最终内联为单组件（见 `roman.duy` 码点映射乘法门）。

## 判别矩阵（shadow 验收时的组件化判别）

| 判别件 | 结果 | 裁决 |
|---|---|---|
| W1：eval 局部槽 → write_mem val='$_t' | ret=7 ✓ | write_mem 局部槽 val 路径通 |
| W2：write_mem 字面 val='3.5' | ret=3.5 ✓ | 数值写入正常 |
| B1：str_cat + str_len → write_mem val='$_n' | 引擎端 ret=0.94921875 ✗ | 引擎端 str_len 回执非长度（本地执行器同构件 ret=3，无此现象） |
| B2：while 迭代判别件 | 装载拒（判别件自身笔误 `$i`），作废 | 撤销 |

## 挂账（引擎端异常·不阻塞本仓判据）

`str_len concept='rm_in'` 在引擎端回执 = **0.94921875**（两次独立组件同值，期望 3）；
本地执行器同构件回执 = 3。归因属引擎内部实现，不在本仓展开，挂账至引擎侧定位修复。
